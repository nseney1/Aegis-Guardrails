# Privacy

Aegis runs on your machine and has no hosted Aegis account or remote telemetry collector. It records local telemetry and Teams evidence. The core and CLI do not implement an HTTP client or open Internet sockets; hierarchy tools also use local Unix sockets for IPC. Child processes can send data elsewhere:

- **Your agent host.** Claude Code, Codex CLI, Gemini through Antigravity, or another MCP client makes its own provider connections. Rules, guidance, prompts, repository text and conversation content supplied to it fall under that host's privacy terms.
- **Layer 2.** `aegis check --full` pipes two prompts, one after the other, to the command you name with `--llm-cmd` or `AEGIS_LLM_CMD`. The first holds your task plan, the function signatures (with their docstrings) and the test names. The second holds the full text of each changed non-test Python file (not the diff; `__init__.py` is skipped), the test output, the Layer 1 results and the risks the first reply predicted. If that command calls a hosted model, that provider receives them. `--plan` and `--plan-file` also enable Layer 2; without any of these options, the plain check does not run the model command.
- **Your GitHub CLI.** `aegis doctor`, `aegis doctor --release`, `aegis sync` and `aegis rule promote`, `demote` and `archive` start your own `gh`, with your own login, to read repository, ruleset, CI-run or attestation data. `aegis check --ci` does too, on a pull-request run and only when a flagged change has no signed approval: it reads the repository, the base branch's rules and the pull request's reviews (in CI with the job's `GH_TOKEN`). `aegis doctor --github --apply` creates one ruleset and `aegis sync --pr` opens a pull request. Scanning, `aegis_list_rules`, `aegis status`, `aegis rule list`, `aegis check` without `--ci` and the agent hooks start no `gh`.
- **Your git remote.** `aegis sync --pr` pushes one `aegis/lifecycle-*` branch, a single commit of the changes under `.aegis/rules` and `.aegis/adjudications`, to the current branch's remote with your own git credentials. The pull request it opens states each rule's evidence state and up to three unlabelled examples per rule.
- **The Teams publisher core.** When an owner configures the service with a separate credential, qualification reader and bounded forge adapter, its gate observes remote refs through `git ls-remote` and repository permissions, PRs and run state through `gh api` GETs. Execution rechecks this evidence; reconciliation also observes remote state. A matching permit and journaled intent allow a qualified `git push`, a forge POST opening a draft lane PR or release PR, or a POST cancelling a superseded push run. PR text carries the qualified commit ID; a push transfers Git objects and their repository content. This core does not activate its own production transport. The supervisor starts a landing component only with explicit owner-supplied argv; that child may run networked `git` and `gh` commands. An automatic merge queue is not provided by this integration.
- **Commands that execute repository code.** Test, coverage, benchmark and user-selected model or driver commands may make their own connections. Offline dependency flags are not a network sandbox.

## What Aegis stores

In your git directory, `<git common dir>/aegis/`, shared by the repository's worktrees and absent from `git status`:

- `state/<ws-id>/ledger.jsonl`: outcome rows with the rule id, outcome, source, host, session id, time, the checked file paths and verdict, and the absolute path of the work tree that wrote the row. Outside a git repository the ledger is `.aegis/state/ledger.jsonl`.
- Check receipts additionally retain per-file tool, verdict, language and missing-driver reason. These evidence rows omit source snippets and diagnostic text.
- `events.jsonl`: one row per event (lease claims and denials, `aegis check --lane` and `--partition`, the hooks' scan-gate and guard decisions, skills sync, host setup, baseline, pack, benchmark and package runs) with the time, event kind, absolute work tree path, host, result and a small detail object. The detail holds counts, lane names and globs, rule ids and lease owner labels; for `lane_check` also the label, the base branch name and the commit ids of the range; for `package` the output path; for `partition_check` the file paths and symbol names of up to 200 predicted call and import edges. It never holds file contents or command text. Outside git it is `.aegis/state/events.jsonl`.
- `gitops.jsonl`, checkpoints and effect locks: Teams intent/result records containing request, lane and actor identifiers, refs, object IDs, expected states and observed outcomes. They are recovery evidence, not a transcript store. These structured fields are validated, not a general text-redaction service. Stop active custodians and reconcile outstanding effects before removing this state.

Ledger and event records retain paths and labels; do not assume those fields are anonymized. Remove their shared `aegis/` state only after stopping its writers; that removes local evidence for all worktrees, not copies already exported to CI.

In the repository, under `.aegis/state/` (git-ignored by `aegis init`):

- `activity.jsonl`: MCP scan and edit events and `aegis scan` runs from the command line (file paths, host, session id, client name and version), read by `aegis status --compliance`.
- `gate_events.jsonl`: decisions of `aegis hook safety-gate`, with the command text cut to 200 characters and known secret patterns redacted.
- `arbiter_predictions.jsonl`: Layer 2 predictions from `aegis check --full`: id, verdict id, time, tree, backend (the program's base name), scope (path and symbol), category, observable (kind and selector), window in days, probability, severity, disposition and outcome. It holds no risk, mechanism or other model text.
- `lifecycle.jsonl`: the rule id and time of each rule moved to the archive.
- `derived.json`: the fitness view `aegis sync` writes. `migrate-backup-*/`: the files `aegis migrate --apply` replaced.
- `team-queue.json` and `messages/`: queue items, claims and recovery text, and oversized output-message files. Queue text rejects credential-assignment syntax; message files may contain the tool response's repository-derived text. Neither is a prompt or transcript anonymizer.
- `unclaim-receipts/`: queue recovery receipts with item, lane, caller and transaction identities. They are validated metadata, not anonymized records; reconcile unfinished queue operations before removing them with the state directory.

State logs have different policies: gate command excerpts use secret-pattern redaction; activity and structured evidence retain their identifiers; prediction rows omit model prose. Migration backups retain the replaced bytes. Stop writers before removing `.aegis/state/`; removing it also removes local queue and compliance history.

Elsewhere in the repository, explicit commands write `.aegis/config.json`, `.aegis/rules/`, `.aegis/adjudications/`, `.aegis/baseline.json`, `.aegis/team/profile.json` and `.aegis/proposals/`. Proposals now include bounded draft text, source/evidence lineage, revision digests and public decision records under `decisions/`; private proposal decisions go to the private insight log instead. Proposal text is canonicalized, redacted and clipped, and URL credentials are removed; verbatim insight prompts are refused. Rules, configuration, baselines and adjudications are repository content, not automatically anonymized. Review them before committing; remove unwanted drafts and decisions from `.aegis/proposals/` and remove any committed copies through your repository's retention process.

In git refs, `refs/aegis/lanes/<lane>` holds the lane name, role, branch, path globs, times and an owner label that defaults to `<user>@<hostname>`. These fields are validated metadata, not anonymized identities. Release a lease with `aegis team release` when its work is finished. Aegis does not push these lease refs; removing a ref does not erase the Git objects or their backups.

The qualification library can write `refs/aegis/qual/<tree>/<leg>`. These refs retain commits containing the complete tested repository tree and qualification metadata, without redacting repository content. They are separate from lease metadata and can keep source reachable after a working branch deletes it. The merge-queue library can also retain a candidate tree under `refs/aegis/merge-queue/` while its issuance is unresolved. Stop writers and reconcile custody before removing the specific qualification refs with Git; unreachable objects, other refs and backups need their own Git retention process.

Lease commands also create `<git common dir>/aegis-lease-scratch/` for private Git metadata and objects. It is not an anonymized store. Stop lease and queue writers and reconcile custody before removing it. Commit and merge jobs, lifecycle PR preparation and explicit hierarchy worktree setup also write ordinary Git objects, refs, indexes and worktrees; removing Aegis state does not erase that repository content or history.

## Teams data

Owner-selected team roots can be outside the checkout. The mailbox holds manifests, messages, checkpoints, acknowledgments and session-binding history. Its bodies and referenced briefs may contain repository text, prompts and handoffs. The board holds post bodies and references under `content/`, immutable `events/` and reader `positions/`. Board text rejects recognized key-shaped credentials; mailbox storage is not a blanket redactor. Treat stored bodies as sensitive even where display guidance is redacted.

Provisioned bases also hold `provision.json`, `team.json`, `host-plan.json`, connections, profiles, session records, role prompts and per-host homes. Launch records under `launches/` include session and process observations, output and `.stop-custody/state.json`; delivery roots hold `reads/` and `wakes/` receipts. Lifecycle roots hold `policy.json` and `events/`. Job stores hold packets, admission and process records, results and step output. These can include paths, prompts, repository text and host transcripts; raw job output, copied source and host-managed transcripts have no comprehensive redaction guarantee. Redacted display fields do not rewrite these source records.

The core wake library can also write turn output under `wake-logs/` in the delivery root. Direct turn stdout and stderr can contain raw text, so treat those logs as sensitive.

The run controller retains `<run>/evidence` separately from the provisioned base. Owner and role turns write raw output logs there. Teardown copies mailbox bodies, job records, launch output, delivery and loop records, requests, events and Codex transcripts, alongside configuration copies, turn accounting and hashes. These copies can contain unredacted prompts, conversation and repository text. Purging the Codex home requires verified transcript copies in this evidence directory; it does not delete those copies.

The run directory also retains `team-state.json`, `team-commands.jsonl`, `inputs/`, requests, events, recipes, loop state, PID and log files, and configured lane worktrees and scratch roots. Workspace job stores retain policy, event histories, grant census records, packets, results, logs and requested kept files. These records and outputs are not comprehensively redacted. Stop their writers and reconcile outstanding operations before removing the run, store, worktrees or scratch; remove retained `<run>/evidence` copies separately after reconciliation.

Explicit hierarchy commands retain review exports (base and candidate source, diffs, history and manifests), composed briefs, handoff acknowledgments and custody records, and native-probe outputs at caller-selected paths. The model-selection library can write a caller-selected decision history. `aegis_core.model_served.observe_served` appends the host, model, level, family and fallback reason that served a decision to that same history. Those fields are configuration tokens, not a transcript. Loop/subscription roots retain status, frozen configuration and notification cursors; the evidence-only watch prototype retains `config.json`, `watch.sqlite`, locks and bridge request/output/result evidence. These may include repository text, prompts, host output and identifiers without comprehensive redaction. Their presence does not mean native watch execution is qualified. Stop the relevant tools and reconcile custody before deleting these output and state roots, including copies retained elsewhere.

Stop the affected sessions, jobs and supervisor components and reconcile unresolved custody before deleting their team roots, delivery roots, lifecycle roots, job stores and private host homes. Remove retained `<run>/evidence` logs and transcript copies separately after reconciliation, even if the operational roots or Codex home have already been removed. Delete separately configured transcript homes through the host's own controls. Removing the checkout or running `aegis uninstall` does not remove these owner-selected locations, forge PRs, remote branches or uploaded CI logs.

The separate manager audit prototype writes an owner-selected configuration and an external store containing `audit.jsonl` and `audit.lock`. Records contain bounded management context, summaries, evidence references, decisions and hashes. They are audit data, not execution authority or a redaction guarantee. Stop the manager server before removing its registration, configuration and audit store; these locations are not removed with the repository ledger.

In your home directory:

- `~/.aegis/workspaces.json`: the absolute paths of the repositories you ran `aegis init` in, and their hosts.
- `~/.aegis/config.json` and `~/.aegis/rules/`: user settings and user-scope rule text. These are not anonymized; remove unwanted entries or rules separately from repository configuration.
- `~/.aegis/link.key`: 32 random bytes (mode `0600` on POSIX), created by `aegis init`, by `aegis rule insight enable` and, when it is missing, by the first insight capture that carries a session id, to pseudonymize host session IDs into keyed `hs` hashes.
- `~/.aegis/insights/<workspace-id>.jsonl`: opt-in user-scope insight rows (mode `0600` on POSIX) holding redacted correction excerpts (`<= 300` characters, with PEM blocks, tokens, `key=value` and prose credentials, emails, home paths and IPv4 addresses scrubbed; a prompt is scanned through its first 4,096 characters, and past that only a whole-word head is kept) and text-free session heartbeats.
- `~/.aegis/backups/`: a copy of each file before Aegis changes it, in one timestamped folder per run: the host config files that `aegis init --host`, `aegis uninstall` and `aegis doctor --fix` change, the host hook files that `aegis hook install --host`, `aegis rule insight enable` and `uninstall --host` change, and the git pre-commit hook that `aegis hook install` (or `aegis init`) rewrites (`~/.aegis` and `~/.aegis/backups` are created with mode `0700`; they can contain other servers' settings).
- The `aegis` entry in each host's own config, written through that host's CLI or config file.
- `~/.aegis/mcp-queue/`: owner registrations, process-bound session grants and authority locks. These retain workspace, lane, capability and kernel-process identities; they are validated authority records, not redacted conversation logs. Stop the queue connection before removing its records.

User configuration and backups are not redacted; backups can preserve credentials already present in host settings. Insight excerpts use the shared secret and personal-data patterns, not a guarantee that all sensitive text is removed. Set `insights.capture` to `off` in `~/.aegis/config.json` to stop passive capture, then remove the workspace's private log to remove its excerpts and private proposal decisions. Remove `link.key` only if you also want to discard session linkage across all workspaces. Unregister host hooks before deleting their configuration entries; `aegis hook uninstall --host` removes installed agent-hook entries.

On Windows, `link.key` and insight files inherit access control from their parent directories; Aegis does not set a Windows access control list for them.

## Caches, scratch and removal

The Go parser cache is under `$XDG_CACHE_HOME/aegis/drivers` (default `~/.cache/aegis/drivers`), `~/Library/Caches/aegis/drivers` on macOS, or `%LOCALAPPDATA%/aegis/Cache/drivers` on Windows. It holds Aegis's parser binary and build/lock files, not repository prompts; no text redaction is applied. Remove that directory while no parser build is active to discard the cache.

Rust test and coverage runs use a persistent `aegis/cargo-target/<workspace-hash>` build cache. Its roots are `$XDG_CACHE_HOME/aegis/cargo-target/` (default `~/.cache/aegis/cargo-target/`) on Linux, `~/Library/Caches/aegis/cargo-target/` on macOS, and `%LOCALAPPDATA%/aegis/Cache/cargo-target/` on Windows. Compiled artifacts can retain repository-derived text and paths; they are not redacted or removed as temporary scratch. Stop consumers and reconcile custody before deleting the workspace's cache directory. Language commands also reuse configured Go and Rust dependency/toolchain caches; remove unwanted copies through those tools' own cache controls.

Temporary directories hold repository exports, private indexes and Git object stores, test homes, JUnit and command output, and driver input. Normal context-manager cleanup removes temporary trees; crashes can leave scratch data. Owner-supplied scratch roots and requested package/report output paths are separate destinations. They can contain complete repository bytes or unredacted command output: remove them after their consumers exit and retain only evidence you intend to keep.

User team overrides are in `~/.config/aegis/team.json`; supervisor state is in `~/.config/aegis/supervisor-state.json` and `supervisor-processes.json`, with identity and attempt records rather than transcripts. Configuration and state are validated, not anonymized. Stop owner-started components and reconcile unfinished attempts before removing those files. They are outside `~/.aegis/`.

Planned implementer launches record lane, claim and kernel-process identities in `<passwd-home>/.config/aegis/writer-bindings.json`, using the account database's home rather than the host's private home. These validated identities are not redacted. Stop the bound writers and reconcile lease and custody state before removing the file. Associated lock files coordinate writers; do not remove active locks to bypass reconciliation.

`aegis uninstall` takes out host registrations, instruction-file blocks, the git hook block and the workspace registry entry. Delete unwanted `.aegis/` and `~/.aegis/` data separately, along with shared Git state, qualification refs, writer bindings, Teams roots, persistent caches, scratch and requested outputs above. Retained `<run>/evidence` copies must be removed separately after reconciliation. These removals do not erase Git history, remote copies, host-provider retention or backups.

## Redaction limits

In v5.0, proposal and insight text is checked for recognized secrets across ignored controls such as CR and NEL. Key bodies split by space, TAB, LF, U+2028 or U+2029 can escape detection. Proposals and insights written by 4.5.x and gate command logs from either version can retain control-split keys. Review those records and proposal history, and rotate any exposed key. Do not rely on redaction before sharing repository state, prompts, transcripts or logs. See [Security](SECURITY.md#what-aegis-does-not-claim).
